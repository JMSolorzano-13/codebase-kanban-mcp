## I. Source of truth
1. Implement only what the active spec.md says. Grill plans inform specs; they are not executable contracts.
2. .sdd-skill/ is cycle memory. Do not write agent cycle files from the indexer or graph-ui.
3. Fix Forward only. Never revert a landed change to "undo" review/test; patch forward and cite the review item.

## II. Languages and layers
1. Engine and daemon: C11 (`-std=c11`), `cbm_` prefix on exported symbols, `-Wall -Wextra -Werror` as in Makefile.cbm. Explicit error paths; no unchecked NULL on allocation/IO.
2. graph-ui: React 19 function components, TypeScript, no bare `any`. Props typed. Tailwind tokens from `graph-ui/src/styles/globals.css`; no new standalone CSS files unless a token cannot express the rule.
3. User-visible UI strings live in `graph-ui/src/lib/i18n.ts` for both `en` and `zh`. Tests may assert English copy.
4. Do not add a JS/Python runtime to the shipped binary path. UI is built and embedded; the process remains the C daemon.

## III. UI chrome vs graph canvas
1. Chrome (Dashboard, tabs, buttons, links, Control, headers, modals) is dark grayscale with contrast between surfaces. Semantic red/amber/green is allowed only for error and health.
2. GraphTab 3D node/edge colors (`colorForLabel` and layout palette) stay categorical. A chrome token rewrite must not recolor the galaxy.
3. Scope CSS variables so GraphTab does not inherit a desaturated `--color-primary` if that would change node hues or graph-only accents.

## IV. Identity and APIs
1. Store key remains project name (`.db` filename). Path 1:1 is admission-only (`cbm_identity_admit` + catalog scan). There is no UNIQUE `root_path` across stores. Bare `{root_path}` is create: owned Path → HTTP 409 `path_exists` (newest owner). `{root_path, project}` that already owns that Path is reindex → HTTP 202. MCP `index_repository` uses the same gate (multi-owner without `name` → isError `path_exists`). Legacy same-Path clones are a Dashboard conflict: enter newest, confirm-delete older. Do not silent-delete aliases. (SDD-ADR-014, SDD-ADR-015, SDD-ADR-018)
2. Dashboard create-index must not send `project` or `project_name`. Name is derived from path (`cbm_project_name_from_path`). Dashboard Reindex sends `{root_path, project}` on the same POST `/api/index`. MCP `name` override is not offered in the create UI flow.
3. Prefer existing HTTP/MCP contracts. New endpoints only when the spec cannot be met with current ones.
4. `indexed_at` is already on `list_projects` / `Project`. Display it; do not invent a second freshness field. `canonical_root` is the group key; display path stays `root_path`. (SDD-ADR-016)

## V. Testing
1. graph-ui behavior in spec: Vitest + Testing Library, same fetch-mock style as `StatsTab.test.tsx`.
2. Every Gherkin scenario maps to at least one test. Do not add product behavior that has no scenario.
3. C tests for any daemon/HTTP change. No C change in spec-001 unless architect proves the UI cannot meet AC without it.
4. New UI tests must not require a live daemon when a mock suffices.

## VI. Security and local HTTP
1. No secrets in source. Cache DBs stay under the user cache dir, not the repo.
2. UI HTTP is loopback by default. Do not widen bind/auth in this spec.
3. Delete remains confirm-gated. Destructive actions stay explicit.

## VII. i18n, a11y, breadcrumbs
1. Interactive controls have accessible names (roles/labels) so tests and AT can find them.
2. Files created or substantially edited for an SDD task carry the `@sdd-task/@sdd-spec/@sdd-decision/@sdd-why/@human-debug` header block.

## VIII. Performance
1. Dashboard must not call `get_graph_schema` per project. That fetch exists for node/edge UI, which this spec removes from home.
2. Control may keep its current `/api/processes` (3s) and `/api/logs` (2s) polls. Do not add a third tight poll for schema.
